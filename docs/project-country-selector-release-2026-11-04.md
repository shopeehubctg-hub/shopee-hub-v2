# Project country selector release candidate — 4 November 2026

Base: latest Production `origin/main` `eb37582`. Branch `codex/project-country-selector-production-20261104`.

The header uses one Project selector and the same country buttons in Price Calculator and Packages & Pricing. Country selection still passes the existing canonical Store ID; it does not copy packages, relabel currency, change grants or move business records. Current automatic Price Calculator supports Malaysia; SG/TH/PH display a concise unavailable message and an Open Packages & Pricing action only when permitted. MY and All Stores retain existing behavior; no fee engine changes are made.

Production has no Project grouping table or lifecycle columns. A new GET `/api/store-project-selector` projects the explicitly reviewed SkinDae relationship only, scoped to tenant `j-packaging` and the existing exact IDs `shopee-skindae-my-by-ctg4u` / `shopee-skindae-sg`, with actual platform validation. Unknown relationships remain individual stores. GoHerb and every other cross-country pair remain ungrouped pending explicit pair review. This is a read-only selector relationship, not a new accounting/store owner.

The handler checks fresh active membership and active tenant before the existing read-only `permission_effective_stores` RPC; that older deployed RPC does not itself validate active flags. It intersects returned canonical IDs with tenant-filtered existing stores, bounds registry reads, and returns only authorized country/store names. RPC or validation failure returns 503 with a generic message and no stale client whitelist. Responses are private/no-store. No new schema, mutation endpoint or migration is included.

Stage continues using its canonical Project management GET through the shared component's `projectEndpoint='/api/store-projects'` prop. Production defaults to the new read-only projection.
